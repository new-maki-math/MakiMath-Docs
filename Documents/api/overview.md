## 认证与通信

登录后发送 `Authorization: Bearer <access_token>`。刷新令牌放在请求体，不使用 Cookie 认证。服务端会检查当前账号与会话，不只看 JWT 是否过期。

先 GET `/api/auth/pubkey`，明文返回 `{ ok: true, pubkey }`。浏览器使用 P-256 ECDH 临时密钥对，把 65 字节 raw 公钥的 Base64 放入 `x-cp`，协商所得 256 位共享位串用作 AES-256-GCM 密钥。报文形状为 `{ "d": "Base64(12字节IV + 16字节Tag + 密文)" }`。

POST/PUT/PATCH 的非空 JSON 请求体必须加密。GET 也应提供正确的 `x-cp`，因为 `/api` 下有内容的 2xx JSON 响应同样会加密。204 无正文，不调用 JSON 解析；错误响应为普通 JSON，不解密。公钥接口使用准确路径，不附查询参数；`/health` 不走封装。现有前端 `src/api/client.js` 已处理这些步骤。

无 `x-cp` 时后端兼容配置中的固定密钥，供基础脚本使用，不能把该密钥分发给浏览器。此协议不替代 HTTPS。以下文档中的请求是**加密前**数据，响应是**解密后**数据，不可直接用明文 POST 到线上。

## 错误、并发和大小

错误主体为 `{ error }`，有些附带 details；客户端根据状态处理，不依赖中文错误句子。

| 状态 | 常见原因 |
| --- | --- |
| 400 | 缺字段、未知字段、类型或加密格式错误、部分数据库检查约束 |
| 401 / 403 | 未登录或会话无效 / 已登录但无权限 |
| 404 | 不存在，或当前账号不能从该公开/私有入口读取 |
| 409 | 草稿并发号、归档限制、重复提交审核、slug 唯一性或关联冲突 |
| 413 / 429 | 请求体过大 / 请求过频 |
| 500 | 未映射的服务端异常 |

讲义草稿使用 edit_version 乐观并发号。保存、局部小节保存和封面修改都可能使它增加；审核通过也会更新来源草稿。读取正文要带目录返回的并发号。409 后保留本地输入，重新读取并处理冲突，不能盲目换个号覆盖。知识点更新没有此字段，当前是最后写入生效。

加密封装后的整个请求体最多 **4 MiB**，不是每个字段各 4 MiB。知识点批量导入另有 data 的 2 MiB 限制。单个源码上限为 200000 个 JavaScript 字符长度，不等于字节数；封面和 Base64 也占请求体空间。列表尚未分页，默认限流每分钟 300 次。

## 数据怎么分开

讲义目录接口不带 source，小节正文按版本、章 slug 和节 slug 单独读取；封面也单独读取。讲义身份 id、版本 id、edit_version、章/节 occurrence_id 各有用途，不能互换。普通整树保存仍会替换目录，不是局部 PATCH；只改一个已有小节时可以用专用保存接口。

后端仅透传 Typst 源码，不生成 AST，也不检查源码宏是否存在。讲义审核快照固定作者源码，公共知识点仍按 slug 取当前有效内容。知识点或讲义均没有旧动画字段及场景执行接口。
