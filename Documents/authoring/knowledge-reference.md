# 知识点正文、引用与掌握

## 知识点正文

知识点由管理员维护 title 与 source。编写时采用**一个完整 MM box 作为正文**，例如：

```typst
#mm-box-definition[
  设数列为 $a_n$，这里填写定义及所需公式。
]
```

知识点名称由 title 字段提供，读取器会把它放入首个顶层 MM box 的标题区域，覆盖该框的补充标题。引用中的掌握按钮也挂在这个首框上。不要为同一个知识点额外包一个外层框，也不要在正文重复堆叠多个知识点框。

这是正文编写约定，**当前前后端没有校验 source 是否恰好只有一个 box**。后端只检查非空字符串及长度。若正文没有顶层 MM box，仍可能显示文本，但引用中的首框标题与掌握按钮不能按约定挂载。应由管理员先整理内容，不能写成“保存会自动拒绝多框”。

## 在讲义中引用

```typst
先阅读定义，再思考例题。

#mm-knowledge(slug: "sequence-limit")

#mm-box-example[这里写作者自己的例子。]
```

slug 最长 100，由小写字母、数字和分隔用连字符组成。宏只接受一个名为 slug 的静态字符串参数，不接受知识点 ID、版本 ID、正文副本或旧的引用注释协议。

讲义小节保存完整 source。后端不解析宏，不检查引用目标，也不生成引用实例 ID、references 或 warnings。复制、剪切、重复引用都保留为普通源码操作。章、节 occurrence_id 仍需保留；源码内的引用没有后端 occurrence_id。

阅读时前端通过 `/api/knowledge-points/by-slug/{slug}` 读取当前 active 正文。知识点更新会影响之后重新读取的引用，**讲义审核快照不冻结公共知识点正文**。404 显示“知识点不存在或已不可用”的占位；其他请求失败显示加载失败并可重试，其他内容继续展示。知识点正文中的嵌套引用暂不展开，不递归请求。

## 搜索插入与复制

讲义小节编辑器可通过“插入知识点”入口搜索，也会在合适的 `#mm-knowledge` 输入位置自动打开选择框。选择后插入上述完整语法。字符串、注释、原始文本中的同名片段不作为自动触发位置；已有有效引用不会被随意替换。选择期间编辑器内容版本变化，会要求重新选择插入位置。

全站搜索中的知识点结果可在弹层读取详情、查看直接前置并标记掌握；详情提供引用代码复制。搜索知识点插入与普通搜索阅读是两个入口，不会因为打开详情就修改讲义。剪贴板不可用时按界面提示手动复制。

## 掌握状态

掌握状态以接口返回的知识点永久 `id` 为键，保存在当前浏览器 IndexedDB。同一知识点的重复引用与知识库详情共享掌握状态；支持时通过 BroadcastChannel 通知同源其他标签页刷新。它不按 slug、标题、讲义位置或版本记账，也没有跨账号、跨设备同步接口。

浏览器存储不可用时提示错误或禁用写入；不要把保存失败显示成已掌握。清理站点数据会影响本地记录。删除知识点不会自动清理已有本地掌握记录，重新创建同 slug 的知识点得到新 ID，不继承旧 ID 的掌握状态。
