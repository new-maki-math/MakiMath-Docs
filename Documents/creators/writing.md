# 编写正文与公式

## 我是老手

如果你已经用 Typst 写过讲义，文字、公式、标题和列表的基本写法可以继续沿用。但这里不是把一份 Typst 工程编译成 PDF，而是把已适配的语法渲染为网页内容。能在官方 Typst 编译器里通过的源码，不一定能原样放进 MakiMath。

**1. 写小节正文，不用准备整份工程**

工作台已经负责组织讲义、章节和小节，每个小节对应一篇源码。打开小节后直接写正文即可，不需要加文档头，也不用通过 `#include` 拼接其他文件。

正文中的 `=`、`==` 等标题只组织当前小节内部的内容，不会在工作台目录里创建新的章节或小节。讲义名称、简介和封面也在对应面板里填写，不必再用源码制作一套。

**2. 公式照常写，程序和纸张排版不能照搬**

平台适配了常用公式、文本结构和部分静态样式，但不会执行完整的 Typst 程序。迁入旧讲义时，可以先按下面的区别处理：

| 以前在 Typst 中的做法 | 在 MakiMath 中怎么处理 |
| --- | --- |
| 直接写文字、标题、列表和数学公式 | 沿用基本语法，结合预览检查显示结果 |
| 使用 `#text`、`#align`、`#table` 等官方函数 | 使用平台已适配的参数；支持这个名称不代表支持它的全部官方能力 |
| 用 `#let` 定义变量或函数，用循环生成内容 | 当前不执行，改为直接写出内容 |
| `#import` 模板或包、`#include` 其他文件 | 当前不执行；把实际正文放进对应小节 |
| 用 `#show` 规则统一改写内容样式 | 当前不执行，教学内容优先使用 MM 宏 |
| 设置纸张、页眉页脚、页边距或强制分页 | 网页正文不按这些规则排版，纸张输出使用讲义打印功能 |

部分 `#set text(...)` 静态参数已有适配，但不能因此把整份模板中的 `#set`、`#show` 设置一起搬进来。遇到提示时，先检查具体参数，而不是只看命令名称。

平台的打印功能也是对网页中的讲义内容进行分页，并不是调用完整 Typst 编译器。所以不要预期打印结果与原来 PDF 的换行、分页完全相同。

**3. 自定义教学样式改用 MM 宏**

以前通过模板自定义的定义框、定理框和题目环境，不能只把命令名称复制过来。MakiMath 提供自己的 MM 宏，用它们表达内容的用途，样式由平台处理：

```typst
#mm-box-theorem(title: [等比数列求和])[
  当 $q != 1$ 时，
  $ S_n = frac(a_1 (1-q^n), 1-q) $
]
```

框的标题、配色和深浅色适配不需要在每篇源码里重新定义。具体写法见[使用 MM 教学宏](./mm-macros.md)。

如果这个定理已经在公共知识库中，就不用再写一份定理框。可以[引用对应知识点](./knowledge-references.md)，再在前后补充自己的讲解。引用的是知识库当前内容，不是固定版本的副本；读者的掌握记录也会随同一个知识点在不同讲义中共用。

**4. 迁入已有讲义时，先试一个小节**

先选一篇有代表性的小节，移除工程导入和纸张设置，把旧的自定义环境换成 MM 宏，再查看公式和嵌套内容是否正常。遇到未适配语法，预览会保留相应片段并给出诊断，不要只凭“保存成功”判断整篇内容都能正确显示。

确认写法合适后，再通过[批量导入小节](./import-export.md#把多个-typst-文件放进一个章节)整理其余内容。填写“Typst 版本”只是记录讲义使用的版本信息，不会切换到一个完整的官方编译环境。

如果是第一次接触 Typst，可以从下面这段正文开始。

## 先写一段能读的正文

把下面这段内容放进一个空白小节：

```typst
我们先观察数列 $a_n = frac(1, n)$。

当 $n$ 越来越大时，$a_n$ 会越来越接近 $0$。
接下来要讨论的，就是怎样把“越来越接近”说清楚。

== 先区分两个问题

- 数列是否有极限？
- 如果有，极限是多少？

不要把“有极限”和“极限等于零”混为一谈。
```

普通文字可以直接输入。两段之间留一个空行，会形成两个段落；为了编辑方便而在同一段中换行，不等于要求读者也在这里换行。

右侧预览会随源码变化。预览正常后记得保存：能看到内容，只说明它已经被渲染，并不代表已经写入浏览器或服务器。

## 标题、强调和列表

正文标题使用等号，等号越多，标题层级越深：

```typst
= 数列极限
== 极限的定义
=== 怎样理解这个定义
```

这些是小节正文内部的标题，不会替你在工作台里新建章节或小节。小节名称已经在页面上显示时，也不必在正文开头重复写同样的大标题。

需要强调一句话时，可以使用 `#strong[...]`；补充语气可以使用 `#emph[...]`。

```typst
#strong[先判断是否满足条件，再使用结论。]

#emph[这里暂时不讨论无穷远处的情形。]
```

这里的方括号装的是内容。括号前的命令决定怎样显示这段内容，括号里仍然可以写文字和行内公式。

并列内容使用 `-`，有先后步骤的内容使用 `+`。列表项之间先保持简单，不要为了缩进效果加入大量空格。

```typst
- 定义说明这个概念是什么。
- 定理说明在什么条件下可以得到什么结论。

+ 检查定理的条件。
+ 写出可以使用的结论。
+ 代入当前问题。
```

## 写行内公式和独立公式

一对美元符号之间是数学公式。紧贴内容时，公式跟随文字排列：

```typst
设 $a_n = frac(1, n)$，则每一项都大于 $0$。
```

希望公式单独成行时，在美元符号内侧留空格：

```typst
$ lim_(n -> infinity) frac(1, n) = 0 $
```

这是 Typst 写法，不是 LaTeX。比如分数写 `frac(a, b)`，不写 `\frac{a}{b}`；希腊字母可以写 `alpha`，不需要加反斜杠。下面这些可以逐条放进编辑器观察：

| 要表达的内容 | 写法 |
| --- | --- |
| 下标和上标 | `$a_n$`、`$x^2$` |
| 多个字符作为上下标 | `$a_(n+1)$`、`$x^(n+1)$` |
| 分数 | `$frac(a+b, c)$` |
| 根式 | `$sqrt(x)$` |
| 极限 | `$lim_(x -> 0) frac(sin x, x)$` |
| 求和 | `$sum_(k=1)^n k$` |
| 积分 | `$integral_0^1 x^2 dif x$` |
| 常用集合和符号 | `$bb(R)$`、`$alpha$`、`$infinity$` |

数学环境中的多字母名称可能被当成命令或符号。想在公式里放一小段普通文字，要使用英文双引号：

```typst
$ x > 0 quad "时，有" quad x^2 > 0 $
```

## 矩阵、分段表达式和表格

矩阵用 `mat`。逗号分隔同一行的元素，分号分隔不同的行：

```typst
$ A = mat(1, 2; 3, 4) $
```

分段表达式可以使用 `cases`，用 `&` 对齐条件：

```typst
$ f(x) = cases(
  x^2 & x >= 0,
  -x & x < 0
) $
```

文字表格使用 `#table`。下面是两列表格，每两个内容块组成一行：

```typst
#table(
  columns: 2,
  [数列], [极限],
  [$frac(1, n)$], [$0$],
  [$frac(n, n+1)$], [$1$]
)
```

先从短公式和简单表格开始。公式很长时，考虑按推导步骤分开书写，而不是把字号一直缩小。特别复杂的数学排版能否显示，需要结合预览诊断确认。

## 使用预览与同步滚动

编辑器和预览是两个区域，可以分别滚动。长小节中，如果希望阅读位置互相跟随，可以开启“同步滚动”；不需要时再关闭。

同步滚动用于帮你找位置，并不意味着源码每一行都对应预览里的一行。一个较短的命令可能渲染出很高的表格或教学框，因此对齐位置可能存在偏差。

## 预览出现诊断怎么办？

先查看“文档诊断”中的行号、列号和说明，再回到对应位置检查。常见问题包括少写一个方括号、公式没有闭合、参数类型不对，或者使用了平台尚未适配的语法。

可以先把出问题的一小段单独留下，去掉复杂嵌套，逐步补回。直接复制整份 LaTeX 或 Typst 工程，通常不如先确认其中一段的写法有效。

MakiMath 目前适配的是常用 Typst 语法和 MM 教学宏，不是完整的 Typst 编译环境。自定义函数、循环、`import`、`include`、`show` 规则和纸张布局等不能按普通 Typst 工程的方式执行。填写“Typst 版本”也不会自动补上这些能力。

定义、例题和提醒不必自己设计边框，接下来可以使用[MM 教学宏](./mm-macros.md)。如果内容已经在公共知识库中，应优先考虑[引用知识点](./knowledge-references.md)，而不是再抄一份。
