# 引用知识库

假设你正在写一份极限讲义，需要用到“数列极限的定义”。一种做法是把定义重新写进正文；另一种做法，是引用公共知识库里的对应条目。

MakiMath 更推荐后者。同一个知识点可以出现在不同作者的讲义中，但仍然来自知识库里的同一份内容。作者负责决定在哪里讲、怎样解释，公共知识则由知识库统一维护。

## 第一次插入引用

在讲义工作台打开一个可编辑的小节，把光标放到想插入的位置，输入：

```typst
#mm-knowledge
```

输入完整宏名，或继续输入左括号时，编辑器会在支持的位置弹出知识点搜索窗口。输入名称查找，再选择结果，编辑器会填好整条引用代码。

选好后看一下预览，确认插入的是需要的知识点，再保存小节。不确定搜索结果时，也可以先到知识库打开详情，阅读内容后再决定引用。

如果没有弹出窗口，检查光标是否在注释、字符串或原始代码块里。这些地方的同名文字不会被当成插入命令。也可以使用下面的复制方式，不必一直重复输入。

## 从知识点详情复制代码

知识点详情中有引用代码和“复制”按钮。复制后粘贴到小节源码即可。引用长这样：

```typst
#mm-knowledge(slug: "sequence-limit")
```

这里的 `sequence-limit` 只是示例。实际使用时，复制目标知识点给出的代码，不要直接照抄示例中的标识。

`slug` 是知识点标识，不是标题，也不是数据库中的数字 ID。保留 `slug:`、英文双引号和括号，不能只写知识点中文名称。

详情中的“添加到我的讲义”是另一个入口：选择已有的本地讲义或可编辑在线草稿，再选择章节和小节，引用会追加到该小节末尾并保存。它不会替你创建缺少的章节和小节；还没有讲义时，先到工作台建好目录。

## 在引用前后写自己的讲解

插入引用后，可以照常在前后增加正文：

```typst
先看一个例子：数列 $a_n = frac(1, n)$ 的每一项都不等于零，
但这不妨碍它越来越接近零。

#mm-knowledge(slug: "sequence-limit")

回到刚才的例子，定义中的条件需要对后面的所有项成立，
不是只找到某一个足够接近零的数就可以。
```

作者可以改变引用的位置、顺序和前后的说明，但不能在这条引用里面修改公共知识点正文。想增加一种理解，就把解释写在前后；发现公共表述有错误，则需要交由知识库维护者修正。

知识点会带着自己的教学框显示，不需要在外面再写一层 `mm-box-definition` 或 `mm-box-theorem`。直接引用也能显示该知识点的掌握按钮。

## 为什么掌握记录能在不同讲义里共用？

你在讲义中看到的是同一个知识库条目，不是作者复制出来的独立副本。读者在任何一份讲义中把它标记为“已掌握”，其他引用同一知识点的讲义也会显示这个状态。

因此，换一份讲义，不等于把学过的知识全部重新标记。不同的讲解可以帮助读者加深理解，而已经掌握的内容仍然能够辨认出来。

目前掌握记录保存在当前浏览器中，跨讲义共用，但不会自动同步到其他浏览器或设备。直接手写一个相同内容的教学框，也不会自动关联到这条记录。

## 知识库更新后，我的讲义会怎样？

引用读取的是知识点当前可用的内容。管理员修正定义、补全条件或调整公式后，讲义再次读取该引用时，也会使用更新后的正文，不需要每位作者逐份替换。

这并不表示已经打开的页面会实时更新。如果仍看到旧内容，可以重新进入或刷新。由于引用内容可能变化，作者还应注意自己在前后写的解释是否仍然合适。

同样，讲义的审核快照固定的是作者当时提交的源码，包括这条引用代码，并没有把知识点正文冻结成旧版本。审核通过后的讲义仍会读取公共知识的当前内容。

## 引用没有显示怎么办？

先检查代码是否完整，以及标识是否来自目标知识点。标题相近的知识点不一定是同一个条目，最好重新从详情复制一次。

如果知识点被归档或删除，引用位置会显示不可用提示。网络请求失败时可以重试。保存源码成功，不代表所有引用都已经验证通过；平台不会因为一个暂时找不到的标识就禁止保存，所以保存后仍要检查预览。

导出讲义 JSON 时，只保留引用代码，不会把知识库正文一起打包进去。换设备后可以继续通过平台读取引用，但不能因此保证断网时也有完整内容。

当前知识点正文中的嵌套知识点引用暂不展开。编写讲义时，按需要在小节正文中分别引用即可。引用也不会自动补齐所有前置知识，需要作者根据读者的基础安排讲解顺序。
