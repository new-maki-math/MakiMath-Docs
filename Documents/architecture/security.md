# 通信安全与数据保护

为保障网络传输过程中的讲义数据完整性与访问规范，MakiMath 建立了一套轻量的通信安全与权限控制机制。

---

## 核心设计考虑

| 考虑维度 | 平台处理方式 |
|---|---|
| **网络数据保护** | 请求与响应数据在网络传输中经过自动编解码处理，减少明文直接暴露，保障基本的数据完整性。 |
| **会话状态管理** | 密钥仅驻留于当前运行时的内存中，不落盘存储，页面刷新后自动重新建立。 |
| **开发无感接入** | 框架底层在拦截器与中间件中统一接管通信编解码流程，上层业务开发保持常规的 JSON 数据交互体验。 |
| **访问权限控制** | 结合 JWT 会话与三级角色权限控制（普通读者、课程编者、系统管理员），按需限制接口访问范围。 |

---

## 数据流向示意

业务代码与底层通信处理解耦，整体请求与响应流向如下：

![通信与数据流向](/images/arch-security-handshake.svg)

### 1. 客户端拦截处理
- 前端在统一的请求封装层中，自动对发送的数据进行序列化与编码封装。
- 业务组件直接使用常规的异步请求函数，无需在代码中手动编写加密逻辑。

### 2. 服务端中间件处理
- 后端 Fastify 服务在请求入口处配置统一的中间件插件。
- 数据到达具体路由处理函数前，已自动完成解码与格式转换；返回时同样由中间件统一封装后输出。

---

## 权限控制体系

除通信层的数据保护外，平台主要依托基于角色的访问控制（RBAC）划分操作界限：

- **普通读者**：免登浏览全平台公开课程与讲义内容。
- **课程编者**：经授权后获得讲义工作台操作权限，可创建、编辑与维护分配范围内的讲义与依赖关系。
- **系统管理员**：负责邀请码发放、用户权限配置与核心数据管理。
